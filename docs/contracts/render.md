# Render contract

`aftergrid render <finding-dir> [--png]` turns validated source into the Reader artifact. Implementation: `src/commands/render.ts`, `src/render/`. Reference the output is compared against: the hand-authored `render/finding.template.html` in the exemplar Findings (`ag-finding-exemplars-a2f`).

## Order of operations

1. Validate the whole Finding with the shared validator. Any error (schema, hashes, references, template, chart subset, digest, Decision bindings) refuses the render and leaves previous outputs untouched. A **fired falsifier is not one of them**: a Finding whose only non-passing Check is a `kind: falsifier` recorded against its `expected_outcome`, with an outcome of `inconclusive` or `needs_reframing` to match, is valid evidence and renders (`docs/contracts/checks-and-results.md`). The Finding that says its own Answer did not survive is exactly the Finding that must reach its Reader.
2. Load results; resolve every token through the shared strict resolver, which also enforces the export allowlist and the provisional policy. A value outside `export_policy.allowed_fields` cannot appear anywhere: prose, table, chart data, chart text or metadata.
3. Render each chart: the validated Vega-Lite spec, `data` bound by the renderer to the exported columns of its result set (numeric columns as numbers, everything else as saved), the pinned house style applied as the Vega-Lite `config`, title set to the resolved chart title, rendered to SVG in Node with no canvas. The SVG gets `role="img"`, a `<title>` (the Claim) and a `<desc>` (the description). With `--png`, a WASM rasterizer writes a preview; it needs a TrueType font (`AFTERGRID_FONT` or a common system path) and says so when none is found.
4. Give every resolved value token a provenance popover. In prose, Claim sentences, populations, caveats, limits and numeric table cells, the value is a focusable `<span class="ref">` whose `<span class="tip" role="tooltip">` (linked by `aria-describedby`) lists, from the pinned manifest: the saved result file, row key and column with its unit; the query that produced it, its dialect, run date and mode, with the SQL hash; the retained inputs it ran on and their capture date; and the definition it uses with its version, recorded lifecycle and recorded approval, always marked "recorded, not verified here". A `derived` value first states its operation and operands, then the trail of its first operand. An `ext` value states what it is, that it is not a measurement, and where it is written down. The footer names the memo token. Chart titles and descriptions inside SVG stay plain text. The popover opens on hover, keyboard focus or a tap of the value; it is CSS only, contains spans only (so it is valid inside headings and paragraphs), and spans the reading column below the value's line.
5. Build one HTML file: draft banner (any readiness other than verified `ready`), title, Reader/owner/generated/revision line, Answer (memo) with the material caveat of the answer-bearing Claim beside it, Decision it informs, one section per Claim in manifest order (type label, sentence, memo body with `<!-- chart -->`/`<!-- table -->` markers replaced by the rendered figure with its data table or the table, who-is-counted / compared-with / when, expandable exclusions and limits, expandable calculation listing the resolved evidence references, definitions, derivations and typed external sources, a per-Claim question link), How we checked (generated facts, each with its own mark, never one badge: Checks by outcome, a fired falsifier as its own fact in the Question's own words — `Falsifier: <statement> — recorded fail; this Finding is inconclusive`, with a `no` mark, and kept out of the Checks-that-did-not-pass line so it is said once, definitions with recorded lifecycle and approval note, reviews with staleness, publication approval, Snapshot guarantees, coverage) one **Counter-metric** fact per `counter_metrics_reported` entry, each its own fact beside the decision metric's Definition fact and never folded into it — `Counter-metric <id>: <resolved value> — <why from the definition>` with a warning mark, or `Counter-metric <id> — not computed: <reason> — it was named because: <why>` with a no mark, the value carrying the same provenance popover every other number carries; and, on a draft whose published decision metric names a counter-metric the Finding reports nothing for, `Counter-metric <id> not yet reported` with a no mark — only a draft reaches the renderer with one, because in a complete Finding it is an evidence error and the render is refused) followed by the memo section, What would change our mind (memo), the single Reader action (mailto with Finding and Claim ids only, plus copyable owner contact and ids), Appendix (memo), footer (generated-at, coverage, canonical location, "cannot know whether a newer revision exists").
6. Refuse to write if any output byte sequence contains `export_policy.private_marker`. Preflight every destination, reserve `render/` for generated output (source evidence and pinned definitions cannot live there), stage all files, and restore prior outputs on a recoverable replacement failure. A successful render removes obsolete SVG/PNG previews, including old PNGs when `--png` is omitted; authored templates remain. This is a single-writer update with rollback, not a crash-atomic directory transaction or cross-process lock.

The **Data** fact reports what the Finding kept, from `snapshot.inputs` and never from the guarantee list: retained inputs with a held guarantee ("Retained inputs are kept: … are possible", ok mark); retained inputs with an empty guarantee list, the state `capture` leaves and `execute` returns to when a run saved no result ("kept, but no replay or rerun from them has been recorded yet", warning mark); no retained inputs on the recorded path ("No copy of the data was kept…", no mark); no retained inputs otherwise ("Inputs were not retained; these numbers are not reproducible.").

## The recorded path

When any execution was run by the harness rather than by an aftergrid adapter, or any Check outcome was reported rather than executed (`docs/contracts/record.md`, ADR 0010), *How we checked* carries one more generated fact, with its own mark, beside the others and never instead of them: **How this was run** — "Queries and Checks were run by the Operator's tool `<tool>`; aftergrid recorded them and did not rerun them." The **Data** fact stays separate and reports what the Finding KEPT, which is `snapshot.inputs` and never the guarantee list: with retained inputs it says "Retained inputs are kept: `<guarantees>` are possible" with an ok mark; with none and a recorded tool it says "No copy of the data was kept. The saved results replay byte for byte; the queries cannot be rerun here" with a negative mark; with none and no recorded tool it stays "Inputs were not retained; these numbers are not reproducible." A recorded Finding retains nothing and still guarantees `artifact_replay`, so keying that fact off the guarantees would tell a Reader inputs were kept on the one route where none ever are. The provenance popover on each value says the same about its own number — for a recorded execution, "Data it ran on" names the source and the tool that read it, instead of reporting a retained copy that was never meant to exist.

## Safety

Every interpolation is HTML-escaped, including authored Claim text and text-valued result cells. Token values are inserted as escaped text after parsing Markdown, so a result value cannot manufacture Markdown links, images or blocks. Memo markdown is rendered with raw HTML escaped, images dropped and links limited to `http(s):` and `mailto:`. Chart SVG comes from Vega on data the renderer bound; resource-bearing SVG attributes may reference only local fragments, never external resources. No script runs on the page.

## Fonts

The default typeface is the system font stack, which embeds nothing. An Instance may set `render.font` in `aftergrid.yaml`: `preset: geist` embeds the Geist variable font shipped with the Engine (`fonts/geist`, SIL Open Font License 1.1), or `family` plus `files` embeds the Instance's own `woff2`/`woff`/`ttf`/`otf` files, each resolved inside the Instance root. Embedding is by `data:` URI in a `@font-face` rule, so the HTML stays self-contained and never links a resource. The same family is applied to chart text, and the first `.ttf`/`.otf` file is handed to the PNG rasterizer in place of the system lookup. A file outside the root or of another format is an `instance_config` error and nothing is written.

## Renderer upgrades

`renderer.version` and `renderer.house_style_version` are part of the content digest, so a renderer upgrade is a content change. A Finding pinned to an older renderer still renders, as a labeled draft preview. To publish it under the new renderer, an Operator re-pins the manifest to the running versions, which produces a new digest, and the required reviews and the publication approval are recorded again against that digest; nothing is re-signed automatically. If a Decision record cites the revision, the re-pin is a new revision of the Finding, because a cited revision never changes under its record. `scripts/repin-renderer.mjs` performs the re-pin and, only with `--resign-fixtures`, re-binds the synthetic reviews and attestations of the Engine's own fixtures.

## Pinned versions

`renderer.version` and `renderer.house_style_version` in the manifest must match `RENDERER_VERSION` and `HOUSE_STYLE_VERSION` in `src/render/charts.ts` for a publication render; a mismatch forces a visibly labeled draft preview and reports both versions (the digest already covers them). The manifest and its reviews are never repinned by rendering. The house style: gray plus one accent, no gridlines, direct axis labels, chart title states the Claim, legends off by default, system font stack. Direct value labels on marks are the chart author's job (`/iterate-visual`), expressed in the spec as a layered `text` mark.

## Committed renders are checked

A render committed to the repository is a claim about what the renderer writes, and a claim nobody re-checks goes stale silently: `verifyGeneratedOutputs` compares the bytes only when something is published, so a manifest change can leave a committed page carrying the old wording until some later change happens to regenerate it. `src/exemplar-render.test.ts` checks it on every test run: for every exemplar under `fixtures/instance/analytics/findings` that commits `render/finding.html`, it copies the Instance to a temporary directory without that `render/` directory, runs the CLI's `render` there in its own process — one render per process, which is what gives the canonical Vega SVG def-id numbering — and compares `finding.html` and every chart SVG byte for byte, plus the set of generated file names in both directions. The remedy a failure names is `node src/cli.ts render <finding-dir>`, followed by committing the regenerated files; a failure after a renderer-version bump means re-pinning with `scripts/repin-renderer.mjs` first. Nothing is normalized before the comparison: `generated_at` comes from the pinned manifest and the font comes from the Instance's own `render.font`, so a difference is a real difference and not a machine's. PNG previews are excluded from the byte comparison for the reason publication excludes them — the WASM rasterizer's output depends on the font file it is handed — and a committed PNG is checked for presence and pixel dimensions only.

## Accessibility and phone

Skip link, semantic headings, `<details>`/`<summary>` for every expansion (keyboard operable), provenance popovers reachable by keyboard focus and described to assistive technology through `aria-describedby`, `scope` on table headers, labeled inline SVG, a viewport meta tag, a 40rem column with 1rem gutters, single-column definition lists and scrollable tables under 30rem.
