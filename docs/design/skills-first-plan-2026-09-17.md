# Skills-first product direction

Patrick's 2026-09-17 instruction supersedes the earlier CLI-led launch sequence: make aftergrid a practical
analytics skills library in the company of Matt Pocock's skills, Compound Engineering and pstack, with the
skills, examples, landing page and content to support that position. This is a product direction, not a claim
of equivalent adoption or independently measured superiority.

## Product

Install analytical judgment into the agent people already use. A person can start with a CSV, a notebook,
warehouse access or an unfinished question. Ordinary skill use must not first require the Engine, an Instance,
GitHub approval, a manifest or an adapter. The existing Engine remains an optional path for retained evidence,
typed Claims, deterministic Checks and publication controls. Its real approval requirements remain intact.

The working loop is question → explore/define → plan → investigate → communicate → challenge → learn.
Use only the steps the task needs. A portable analysis is not automatically an Engine Finding, and a saved
lesson is proposed context, not an approved Metric definition.

## Deliverables and ownership

- Skill lane: portable paths for the existing nine skills; add `explore-data`, `define-metric`, `plan-analysis`,
  `diagnose-change` and `learn-from-analysis`; preserve checked-Finding procedures in optional references.
- Site lane: responsive static home, searchable skill catalog and detail pages, examples, quickstart and
  fieldnotes, generated deterministically for the existing GitHub Pages deployment.
- Research lane: primary-source benchmark of the three references; concrete practices adapted to analytics.
- Coordinator: runnable synthetic skills lab, substantial guides/fieldnotes, README and positioning,
  independent behavioral trials, integration, tests and release evidence.

Existing site work is reconciled into this implementation rather than run as a second redesign. The old
explorer remains a historical artifact. The diagnosis skill proceeds under the new explicit instruction;
its earlier hands-on-retro dependency does not prevent this portable workflow. The real hands-on study and
human publication approvals still require real participants and cannot be marked complete by this work.

## Acceptance evidence

1. Each portable skill is useful when installed alone. Its required local resources travel with it.
2. New workflows contain domain-specific decision rules and useful outputs, not generic role prompting.
3. Independent agents use skills on bounded datasets without the answer key; review their actual artifacts
   against numerical checks and analytical failure cases. Report scope and limitations, not a benchmark win.
4. Examples contain real inputs, executable calculations, actual recorded skill outputs and honest caveats.
   Synthetic teaching datasets are clearly labeled. NYC examples retain their unapproved status.
5. The site and docs agree on names, invocation, prerequisites, installation and completion claims. Links,
   generated drift, keyboard/mobile behavior and content are checked.
6. Existing Engine tests, fixture validity and packed distribution continue to pass. No npm publication,
   paid offering, fabricated approval or private data is needed for this skills-first release.
