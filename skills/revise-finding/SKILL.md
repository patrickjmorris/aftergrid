# Revise a finding

Work on the artifact the user supplied: memo, notebook, chart, or analysis document. Preserve its evidence trail and follow the requested scope. For an aftergrid Finding, use [the Engine revision procedure](references/engine-workflow.md); it classifies changes, pins revisions, and invalidates reviews as required.

## Classify the feedback before changing the answer

A **presentation edit** changes wording, structure, typography, or labels while preserving meaning. An **interpretation edit** changes causal strength, uncertainty, exclusions, the emphasized comparison, or what the reader would conclude. A **calculation edit** changes data, filters, joins, metric definition, denominator, aggregation, population, or window. Classify by consequence, not by how small the text edit looks.

Read the original question and supporting evidence. Resolve feedback that conflicts with the evidence explicitly. A request to make an inconclusive result “more confident” cannot be satisfied by hiding its caveat; improve clarity while retaining the uncertainty.

## Apply the narrow change

For presentation edits, retain exact values and source references, then compare the revised claims with their originals. For interpretation edits, re-evaluate the evidence and caveats before rewriting, and obtain a fresh analytical review when needed. For calculation edits, rerun the affected computations and checks through existing authorized tools; if access is unavailable, leave the affected conclusion unresolved and state what needs to run.

Preserve a useful change record in the existing artifact or version system: request, edits made, calculations/checks rerun, resulting change in conclusion, and remaining limits. Do not claim an old review covers new evidence or create publication approval. Deliver the revised artifact and whether the reader's decision should change as a result.
