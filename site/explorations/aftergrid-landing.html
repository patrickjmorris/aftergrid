How it works

Two people, one document.

The Operator runs the analysis in Claude Code. The Reader gets a document on a phone. Neither has to learn the other's tools.

OperatorIn Claude Code
  1. 01Set up the InstanceMetric definitions, table docs, Reader profiles, decision log./setup-aftergrid
  2. 02Sharpen the questionDecision, metric, population, window, falsifier./grill-question
  3. 03Checked analysisChecks first, then numbers, then two review subagents./analyze
  4. 04Review the PR, renderApproval binds to the content digest.aftergrid render
ReaderOn a phone
  1. 01Ask"Did the checklist help?" in plain words.
  2. 02Read the answerOne sentence, then who was counted and compared with what.
  3. 03InspectExpand a number: calculation, exclusions, limits, evidence.
  4. 04Question or decideOne action, carrying only the Finding and Claim ids.

Checks

Tests for analysis, the way software has tests.

A Check establishes one stated property. Passing Checks never by themselves make a Finding trustworthy, and the Finding says so.

CheckWhat it establishesThis Finding
unique_usersNo user is counted twice across arms.pass
arm_balanceThe two groups are about the same size, as random assignment should produce.pass
retained_7d_reconcileThe retained count matches the approved definition computed a second way.pass
falsifier_liftThe gap is at least 3 pp with at least five hundred people in each group.pass
references_resolveEvery {{ref}} in the memo points at a saved result row and column.pass
Publication readinessA current human approval bound to this exact content digest.not ready

Revisit

The analysis that re-checks itself.

A merged Finding is a standing test of the decisions that cite it. Revisit reruns the saved SQL on fresh data and re-tests every Claim. Each Decision record names the Claims it rests on, so the decision log becomes a live board of what still holds. The owner judges; the engine never declares a decision holds.
