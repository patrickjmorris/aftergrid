The skills

Nine skills. Four you type, five the agent reaches for.

A skill is a plain SKILL.md any agent harness can read: a procedure written for agents. No user-invoked skill calls another; the agent picks up the model-invoked ones mid-task. Each ships with a docs page and an agents/openai.yaml for harnesses that want one.

You type these

user-invoked
/setup-aftergrid

Scaffold an Instance in your repo, check the dependencies, validate the warehouse connection if you asked for one, install the guardrail hook, and say what is still missing.

Use once per repository.

Read the skill →
/grill-question

Interview you in rounds until a raw ask is a Question: the decision, the Reader, the metric, the population, the window, the primary comparison and a falsifier.

Use before any analysis runs, or when an ask names no metric or window.

Read the skill →
/analyze

The one orchestrator. Raw ask to reviewed Finding draft: clarify, analyze under Checks, write, illustrate, shape, review, check. Halts with a precise reason.

Use to run an analysis end to end, or resume one that stopped.

Read the skill →
/revise-finding

Classify your feedback as presentation, interpretation or numeric. Apply the cheap kind as a new revision; say exactly what the other two reopen.

Use "make it horizontal", "lead with retention", "reword the answer".

Read the skill →

The agent reaches for these

model-invoked
/checked-analysis

Probe the catalog, write the Checks before the analysis SQL, run the queries and Checks, record what ran and on what.

Use after a Question is sharpened.

Read the skill →
/write-finding

Turn a checked Analysis into a Finding: six fixed sections, typed Claims, charts and tables, every displayed value bound to a saved result.

Use once results are pinned.

Read the skill →
/iterate-visual

Render each chart, look at the PNG, score it against the Storytelling with Data rubric, revise up to three times, hand back what still fails.

Use after a chart spec is written or changed.

Read the skill →
/shape-narrative

Answer first. Each Evidence heading states its Claim, each chart title states its Claim, the caveat sits beside the Answer, in the Reader's words.

Use after writing and charts, before review.

Read the skill →
/analysis-review

Method, Question and Reader reviewers dispatched in parallel. Each returns blocking and non-blocking findings, recorded against the content digest.

Use before aftergrid check, or when a revision left reviews stale.

Read the skill →

Install

Runs where your agent already works.

The skills are plain files. skills.sh installs them into more than twenty agent harnesses from this repository, today, with nothing to register. The CLI behind them is not on npm yet.

Any agent, via skills.sh

All nine skills, or one, into the agent you name. Verified on this repository with Claude Code; skills.sh also targets Cursor, Codex, Copilot, Windsurf, Gemini, Zed and others.

$ npx skills add patrickjmorris/aftergrid
# one skill, one agent:
$ npx skills add patrickjmorris/aftergrid --skill analyze -a cursor

Skills run with your agent's permissions. Read them before you use them: each is a short SKILL.md.

Claude Code plugin

The same skills as a plugin. The manifest is .claude-plugin/plugin.json; point Claude Code at a checkout.

$ git clone https://github.com/patrickjmorris/aftergrid
# manifest: .claude-plugin/plugin.json
# also install mattpocock-skills (grilling, writing-for-agents)

Setup checks that mattpocock-skills is present and prints the install line if not.

The CLI

Checks, render, decide and intake. TypeScript sources, no build step, no native compiler. Node 22.18 or newer.

$ git clone https://github.com/patrickjmorris/aftergrid && cd aftergrid
$ pnpm install && node src/cli.ts --help

Or pack a tarball: pnpm pack, then npm install --ignore-scripts ./aftergrid-0.0.0.tgz.

Checks

Checks are written before the numbers.

/checked-analysis writes them first, then runs the analysis SQL. A Check establishes one stated property. Passing Checks never by themselves make a Finding trustworthy, and the Finding says so.

CheckWhat it establishesThis Finding
unique_usersNo user is counted twice across arms.pass
arm_balanceThe two groups are about the same size, as random assignment should produce.pass
retained_7d_reconcileThe retained count matches the approved definition computed a second way.pass
falsifier_liftThe gap is at least 3 pp with at least five hundred people in each group.pass
references_resolveEvery {{ref}} in the memo points at a saved result row and column.pass
Publication readinessA current human approval bound to this exact content digest.not ready

Revisit

The analysis that re-checks itself.

A merged Finding is a standing test of the decisions that cite it. Revisit reruns the saved SQL on fresh data and re-tests every Claim. Each Decision record names the Claims it rests on, so the decision log becomes a live board of what still holds. The owner judges; the engine never declares a decision holds.

Open source

The engine is public. Your context stays yours.

Skills are verbs. Your metric definitions, table docs and decisions are nouns, and they never leave your private repo.

Engine

github.com/patrickjmorris/aftergrid · MIT

  • Skills: /grill-question, /analyze, /revise-finding
  • Checks and the Finding validator
  • Adapters: DuckDB, Postgres
  • CLI: new finding, check, render, decide, revisit
  • Guardrail hook (Claude Code today)

Instance

your-team/analytics · private

  • Metric definitions, versioned and approved by a person
  • Table docs and Reader profiles
  • Golden Questions with expected answers
  • Findings, reviewed as pull requests
  • The decision log
