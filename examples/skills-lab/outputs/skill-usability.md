# Skill usability observations

Applied locally: diagnose-change (conversion and revenue), analysis-review (onboarding draft), learn-from-analysis (proposed conversion lesson), plan-analysis and checked-analysis (follow-up). The ordinary-file routes were usable without CLI/Engine setup or approval ceremony. No skill required unavailable tools for these cases.

Minor friction: diagnose-change requests predictions before each cut but begins by inspecting/reproducing the source. For these very small extracts, reading source rows exposed values before plans were saved; I disclosed this and did not label them preregistered. The follow-up sequence explicitly saved its plan before reading values. A plan template distinguishing “after source inspection, before calculation” from preregistration could make this distinction easier to preserve.

Analysis-review's three lenses were run serially by one agent; complexity did not justify independent reviewers and the assigned scope prohibited extra agents. Its instructions supported this route explicitly. No independence or human comprehension claim was needed.

The learning instructions provided no established lesson-store destination in this fixture; the user's request to save a lesson justified `outputs/learning/lessons/`. The proposed status, evidence links and applicability/counterexample requirements prevented promoting the observed mix shift into a universal rule. No blocked work or missing capability resulted.
